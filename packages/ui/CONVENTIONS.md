# @partyco/ui — конвенции

Обязательны для каждого компонента. Расхождение = баг, а не стиль.

## 1. Никаких «сырых» значений

Ни одного хекса, ни одного px-размера шрифта, ни одного радиуса в коде компонента.
Только CSS custom properties из `@partyco/tokens/css`.

```css
/* ✅ */ color: var(--pc-text-2); font: var(--pc-type-meta); border-radius: var(--pc-radius-sm);
/* ❌ */ color: #a0a8b0;          font: 400 11px 'IBM Plex Sans'; border-radius: 3px;
```

Исключение — `rgba()` от токена через `color-mix()` или готовая `*-gutter`-переменная.

## 2. Стилизация — CSS Modules

Один `.module.css` рядом с компонентом. Vite поддерживает из коробки, скоуп бесплатный,
рантайма нет. Инлайн-стили допустимы **только** для значений, которые вычисляются в JS —
на практике это цвет идентичности участника (он приходит из данных, а не из темы).

```
src/components/Button/Button.tsx
src/components/Button/Button.module.css
```

## 3. Обе темы, всегда

Компонент не знает, какая тема активна. Он ссылается на токены; переключение делает
`data-theme` на корне. **Запрещено** писать `[data-theme="light"]` внутри компонента —
если в светлой теме что-то ломается, значит не хватает токена: добавь его в
`packages/tokens/src/palette.ts`, а не хардкодь ветку.

## 4. Обе плотности

Высоты строк, паддинги и кегль берём из `--pc-row-height`, `--pc-row-padding-x`,
`--pc-row-gap`, `--pc-font-delta`. Плотность меняет **только** геометрию — никогда состав
строки, иерархию или цвет. Если в compact что-то пропадает — это баг.

## 5. Роли цвета идентичности и статусного

**Цвет участника — четыре роли, других нет:**

| Роль | Хелпер | Где |
|---|---|---|
| заливка аватара | `avatarStyle` | везде |
| кромка зоны 2px | `zoneEdgeStyle` | дерево, вкладки, строки |
| подложка гаттера диффа | `diffGutterStyle` | дифф, редактор |
| площадь владения | `ownershipAreaStyle` | карта владения на экране лизов |

Хелперы в `src/identity.ts` — **не собирай `var(--pc-id-…)` руками**, это ловит линтер.

Четвёртая роль добавлена осознанно: на карте владения заливка прямоугольника и есть утверждение
«этим владеет вот этот участник». Инвариант, который правило защищает, не изменился — цвет участника
появляется только там, где он означает владение, и никогда там, где живёт статусный цвет.
Пятая роль потребует такого же обоснования.

**Статусный цвет — точка, пилюля, текст, обводка.** Обводка добавлена там же: на карте прямоугольник
несёт владельца левой кромкой 2px, а состояние — остальным периметром. Это не конфликт, потому что
левая кромка остаётся за идентичностью.

**Запрещено по-прежнему:** статусный цвет как заливка большой области и как левая кромка зоны.

## 6. Обязательные состояния

У каждой панели/списка/таблицы: `empty`, `loading`, `error`. Не «потом» — сразу. Компоненты
из `src/components/States/` для этого и существуют, переиспользуй их.

## 7. Фокус видно всегда

`box-shadow: var(--pc-focus-ring)` на `:focus-visible`. Не `outline: none` без замены.
Любой интерактивный элемент достижим с клавиатуры и имеет видимый фокус.

## 8. Данные приходят пропсами

Ни один компонент не хардкодит контент и не знает про сеть. Никаких `fetch`, никаких
моков внутри компонента: всё, что рисуется, приходит пропами.

## 9. Иконки

Только `<Icon name="…" />` из `@partyco/icons`. Цвет наследуется через `currentColor` —
не передавай `stroke`.

## 10. Доступность

Семантические элементы (`button`, а не `div onClick`). `aria-label` там, где текста нет.
Таблицы — настоящие `<table>` с `<th scope>`. Модалки — фокус-трап и `Esc`.
Анимации гасятся `prefers-reduced-motion` (уже в токенах глобально).

## 11. Экспорт

Каждый компонент реэкспортируется из `src/index.ts`. Пропсы экспортируются как
`export interface XProps`. Никаких default-экспортов.

## 12. Русский в UI, английский в коде

Пользовательские строки — русские (как в дизайне). Имена файлов, компонентов, пропсов,
токенов, CSS-классов — английские. Строки не разбросаны: если компонент содержит больше
двух-трёх подписей, они идут в пропсы со значениями по умолчанию.
